# Antigravity 代理助手 · macOS

这是可双击打开的本地 Mac 应用，按 yuaotian/antigravity-proxy 的使用目的重新实现启动与配置入口。不是上游官方版本，也不包含或移植其 Windows DLL。

## 使用

1. 双击「Antigravity代理助手.app」。也可将应用复制到「应用程序」。
2. 先启动已有的代理软件，查看它实际监听的 HTTP、mixed 或 SOCKS5 端口。
3. 优先点击「自动识别代理」：助手会读取本机代理进程监听端口，并验证 Google 登录接口后保存可用配置。也可手动填写协议、主机与端口。默认 HTTP / 127.0.0.1 / 7890 只是初始值，不代表你的代理实际使用该端口。无需在地址中填写 http://。
4. 点击「检测代理连接」。HTTP 401、403、404 等表示已收到服务器响应，只证明基础网络连通，不证明登录、账号权限或 Agent 可用。
5. 在 Antigravity 中保存工作，使用 ⌘Q 完全退出，再点击助手的「通过代理启动」。
6. 在 Antigravity 中发一条消息，确认 Agent 可以工作。

## 工作方式与范围

通过 Antigravity 可执行文件传入 Chromium 的 --proxy-server 参数，同时为新启动进程设置 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 及小写变量；本地回环地址绕过代理。HTTP 和 SOCKS5 都可选，SOCKS5 的 curl 检测使用代理端 DNS。

不更改系统代理、不修改 Antigravity 应用、不停止现有进程。关闭助手不会停止已启动的 Antigravity。直接从原来的图标启动时，不会由本工具重新设置这些参数。

该方法只能影响支持相应代理参数或环境变量的网络栈。Antigravity 的某些原生子进程可能忽略它们，因此不保证达到 Windows DLL 拦截所有目标进程的效果。curl 检测与 Agent 真实请求是不同路径，需要第 6 步验证。

本版不提供用户名/密码代理认证；推荐本机无认证监听端口。未通过 Apple Developer ID 签名或公证，当前包为本机临时签名版本；在其他电脑使用可能遇到 Gatekeeper 提示。

## 保存位置与卸载

配置：~/Library/Application Support/AntigravityProxyHelper/settings.json

启动日志：~/Library/Application Support/AntigravityProxyHelper/launch.log

删除应用即可卸载；若需清理配置和日志，可自行删除上述 AntigravityProxyHelper 文件夹。

## 源码与构建

源码在「源码/main.swift」。需要 macOS 与 Xcode Command Line Tools。应用使用 AppKit，无第三方包、后台服务或联网下载依赖。

推荐双击「源码/build.command」构建。脚本会通过临时编译覆盖配置处理部分 Command Line Tools 安装中的重复模块定义，不修改系统文件。正常的工具链也可在本输出目录运行：

```sh
swiftc 源码/main.swift -o Antigravity代理助手.app/Contents/MacOS/AntigravityProxyHelper -framework Cocoa
codesign --force --sign - Antigravity代理助手.app
Antigravity代理助手.app/Contents/MacOS/AntigravityProxyHelper --self-test
```
